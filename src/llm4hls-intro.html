LLM4HLS 入门：用大语言模型辅助高层次综合

FPT'26 Design Competition Track A 项目笔记 (ฅ^u u^ฅ)

背景

高层次综合（HLS）可以将 C/C++ 代码自动转换成 RTL（Verilog/VHDL），极大提高了 FPGA 开发的效率。然而，HLS 工具对代码风格有严格要求，写出来的代码性能也可能远不如手写 RTL。

LLM4HLS 的思路是用大语言模型作为 Agent，自动生成符合 HLS 风格要求的 C/C++ 代码，甚至自动添加优化 pragma，从而降低 FPGA 开发的门槛。

项目架构

我们的工作流分为六个阶段：

  1. 需求解析 —— 将自然语言描述的功能需求转换成结构化规范
  2. 代码生成 —— 使用 DeepSeek API 生成 Vitis HLS 兼容的 C++ 代码
  3. RAG 增强 —— 基于 HLS 模式库（7 种常见模式）进行检索增强生成
  4. 编译验证 —— 自动调用 Vitis HLS 进行综合和仿真
  5. 反馈循环 —— 根据编译错误自动修正代码
  6. 性能评估 —— 对比生成的 RTL 与手写 RTL 的时序和资源

关键技术点

RAG 模式库

我们整理了 7 种常见的 HLS 加速模式：

  • 流水线（Pipeline）
  • 数组分区（Array Partition）
  • 数据流（Dataflow）
  • 循环展开（Loop Unroll）
  • 内联函数（Function Inline）
  • 接口综合（Interface Synthesis）
  • 内存重组（Memory Reorg）

DeepSeek API 配置

使用本地代理 127.0.0.1:7897 访问 DeepSeek API。较长的上下文窗口（128K tokens）对于处理 HLS 编译器的完整输出非常有帮助。

初步结果

在简单的矩阵乘法测试中，LLM 生成的代码在时序上已接近手写 RTL 水平（2.2M cycles vs 2.33M），但由于运行时 sqrtf() 不是编译期常量，时序为 25.7ns（手写 5ns），还有优化空间。

后续将继续优化提示词和 RAG 检索策略，争取在 FPT'26 竞赛截止前提交更好的结果。
